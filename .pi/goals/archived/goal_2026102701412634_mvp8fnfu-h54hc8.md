=== Goal ===
Objective: Raise Ornith-1.5-122B IQ3_XS inference speed in Strata on the existing hardware (RTX 3090 Ti 24 GB, i7-10700, 61 GB RAM, PCIe 3.0) by trying the speed ideas from the previous discussion, keeping each change that measurably helps and dropping or leaving opt-in each change that does not.

Ideas to try (best effort, in roughly this order):
1. Free VRAM for expert slots: release or reuse the 3.09 GiB of prompt staging buffers during decode; fp16/int8 KV cache; move token_embd to the CPU; reconsider the default context.
2. Better slot placement: a startup hot-expert profile for Ornith (like Flash-Next's --expert-profile); per-layer slot allocation by traffic.
3. Overlap PCIe and CPU during decode: prefetch the next layer's likely experts (layer L+1's router applied to layer L's output); an adaptive fetch fraction instead of a fixed 0.5.
4. Faster CPU expert kernels: a lossless IQ3_S repack/layout for AVX2, or kernel tuning.
5. Better drafting: n-gram/suffix drafts with MTP; a subset-vocabulary MTP draft head without packed Q8_0.
6. Prompt: a larger default prompt chunk (4096) when it fits.

Success criteria:
- Each idea tried has a recorded before/after measurement on this machine (or a short note on why it was skipped), in docs/work/ORNITH_BENCH.md.
- A final head-to-head table against the current branch baseline (pp512, pp2048, pp4096, tg128, 256-token chat decode with and without --mtp 1), with commands.
- Kept changes are on by default for Ornith only where they measured faster; the others are opt-in or removed.

Boundaries:
- In scope: the src/qwen35 engine, the CPU pool / kernels, setup/launch defaults for Ornith, tools, tests and docs.
- Out of scope: system settings (no sudo; the CPU governor is listed only as a suggestion), hardware changes, other quants, app UI, opening PRs.

Constraints:
- Output-changing optimizations are allowed only if tools/qwen35/ornith_kl.py still passes (KL <= 1.5x the llama.cpp noise floor). Lossless ones must keep identical tokens.
- Qwen3.8 Flash-Next default behaviour unchanged: identical greedy tokens, main build vs branch build, as checked before.
- No new pytest failures vs main in tests/terminal; ctest failures stay a subset of main's.
